# Whatchadoin - 업무 밀도 트래커

할 일을 할 때, 내가 정말 일처리를 밀도있게 하고 있는 것인지 - 아니면 화면만 띄워두고 멍때리거나 파악하는 시늉만 하는 것인지 명확하지 않아보일 때가 있다.
업무 시간동안 작업의 진행 상황 및 속도를 파악하고, self피드백을 위해 진행된 작업 내용에 대한 분석 리포트를 받고자 한다.

----------
phase 1 - 직접 입력

[개요]

주기적으로 app 내의 todo notes를 참조한다.
WYSIWYG markdown 에디터의 형태를 지향한다.

todo note의 변경사항으로 어떻게 작업이 진행되는지 background에서 추적 및 이벤트를 timstamp 단위로 기록한다. (여기에 AI 기반으로 작업이 어떻게 진행되는지를 track하기를 원함.)
작업 종료 후 해당 이벤트에 대한 분석을 받는다.


[리포트 컨셉]
칸반보드와 insight 섹션으로 나뉜다.
칸반보드는 언제 어떤 업무에 집중하였는지 track하기 위해 존재하며, tracker가 시간의 분절 없이 진행했는지를 캐치한다.

[리포트 구현 — phase 1]
선택한 업무일의 events를 재료로 한다. 하루 경계는 새벽 5시 기준(Settings에서 조정 — 자정 넘긴 작업 대응)이며, 그 시각 전 이벤트는 전날 업무일로 묶는다.
- 집중 타임라인(Gantt): 컨셉의 '칸반보드'를 구현한 것. 체크인 응답("X 작업 중")으로 task별 집중 구간(막대)을 만든다. 연속 체크인은 한 막대로 병합하고, 체크인 간격이 주기의 2배를 넘으면 추적 공백(집중 분절)으로 끊는다.
- 노트 활동 트랙: 노트 변경(추가/완료/삭제)을 시간축에 틱으로 표시해 진행을 가시화한다.
- Insights: 활동 구간·총 이벤트·노트 변경(추가/완료)·체크인 횟수·최장 공백 (계산형; AI 분석은 추후 processing crate).


[events 모니터링]
events는 foreground 앱 변경 및 workspace / 체크인 변경사항 추적 등의 이벤트를 저장하는 자료구조이자, 추후 리포트 생성 등에 있어 원본 재료가 되는 데이터들을 저장하는 기능이다.
현재 UI-level에서 명시적인 spec으로서 해당 데이터가 표출되는 구역은 right sidebar 뿐이다.
<잠정구현 - 나중에 변경 가능>
events의 목록이 갱신될 때 마다 view를 갱신하여 표출한다.
우선은 workspace note 변경 및 체크인 응답을 추적하는 것을 목표로 한다.
